Robot Job Board

Tech: HTML, CSS, JavaScript, JSX and React

A job board that is visually similar to a Kanban board. Users can create, read, update, and delete job entries. Each job has an id, name, notes and status. Individuals can save jobs on a specific browser and device. For example, the jobs saved on a Chrome device on a mobile cannot be accessed on a Firefox browser on the same device or a Chrome on a different device. The same is localised and specific.

  • Problem: Tracking multiple job applications in a simple board can get messy without a clear workflow.
  • Constraints: No backend; data is saved locally to a specific browser or device; each job needs an ID, name, notes, and status; optional columns can be hidden or shown.
  • Approach: Created a job form and columns similar to a Kanban board with CRUD operations (add, update, edit, remove) and a clear “Save Job List” step to keep changes; added user-friendly features (quick job name buttons, hide/show list).
  • Outcome: Users can manage a personal job board that stays on the same browser or device, allowing for easy updates and deletions without needing a server.
  1. Fill in the fields of the job form, including id, name, notes and status.
  2. When the data is correctly added, press "Add/Update" job button to add a job to the kanban board.
  3. To save a job permanently to the job list, press "Save Job List".
  4. To edit a job, click the "Edit Job" button to edit a job , fill in the fields specified in step 1 then do steps 2 and 3 to update, using "Update Job".
  5. To remove a job, click the "Remove Job" button then do step 3 to save the changes.
  6. Optional - press "show/hide List" button to show or hide a column.
  7. Optional - press buttons in the Job Name Input fieldset to enter names of jobs quickly.

IP Address Tracker

Tech: HTML, CSS and JavaScript

This project allows a user to view the website or IP address registration data and locate the registration location on the map. An API is used to map a URL address or an IP address to an internet service provider - plus their location and time zone.

  • Problem: Users need a quick way to translate an IP address or domain into a clear network or geographic service location.
  • Constraints: The tool must handle user input for either an IP address or domain, or allow for an empty submission. It includes a map user interface and follows a front-end Mentor challenge. It credits mapping data and services like OpenStreetMap and Mapbox.
  • Approach: I built a search bar and a results panel. If the input is empty, the app prompts the user to get their own IP information. If there is input, it fetches registration data for the provided IP address or domain, updating the text fields and the map.
  • Outcome: Users can get details about an IP address or domain and see its location on a map, along with clearly labeled fields showing the IP, location, time zone, and ISP.
  1. The app will ask to retrieve the user's IP address if no characters or empty characters are submitted
  2. If the user presses cancel, the alert closes and nothing is retrieved
  3. If the user clicks ok, then the IP address information is retrieved
  4. Users can also type in an IP or a worded website home address into the app for its details

Currency Converter

Tech: HTML, CSS and JavaScript

This project allows a user to convert a currency - from one country - to another currency of another country. This uses live data from an API to fetch the conversion rates (1 unit of source currency converted to destination currency).

  • Purpose: A live-rate currency converter that calculates conversions between a chosen source and destination currency and displays rate and timestamp outputs.
  • Problem: Users need up-to-date currency conversions, including the rate and converted total, without searching for exchange rates manually.
  • Constraints: The tool must fetch live conversion-rate data, support many currencies with long dropdowns, and show the timestamp, 1-unit comparison, and converted transaction amount.
  • Approach: I created a form that allows the user to select the source and destination currencies, enters an amount, submits it, and the app then shows the exchange-rate fields and calculated totals.
  • Outcome: A simple conversion process with clear outputs for the exchange rate, calculation timestamp, and both source and destination amounts.
  1. Pick a country source currency from the dropdown
  2. Pick a destination country's currency
  3. Add how much they want to convert
  4. Submit
  5. Once submitted, the app shows the timestamp, 1 unit of the source compared to the destination unit(s), and the total source currency input converted to destination currency.

Colour Game

Tech: HTML, CSS, JavaScript and jQuery

View on a laptop that supports a resolution width of 1380 pixels. Required for a fair experiment. The project investigates whether colour sorting and mixing symbols are effective for colour recognition and colour gradients tasks. In the case of gradients, if someone is cooking meat, recognising the colour changes from pink to brown indicates to someone with colour vision deficiency (CVD) that their food is cooked correctly. Research was conducted using journals relevant to CVD , HCI (human-centred interaction), Psychology and Colour Science

  • Purpose: This is a controlled experiment that investigates whether colour-sorting and symbol-based cues help with colour recognition and gradient tasks, including for colour vision deficiency (CVD).
  • Problem: People with CVD may have difficulty interpreting colour changes, such as gradients. This experiment looks into whether alternative cues can improve recognition accuracy.
  • Constraints: This fair experiment requires a laptop width of 1380px. The participant groups are divided into two: groups 1 to 6 have CVD or simulated CVD, and groups 7 to 12 have normal vision. Access is controlled by participant-specific passwords. The responses are recorded in text files for analysis.
  • Outcome: An app that gathers responses from participant groups under controlled display conditions.
  1. The passwords for all participants are the passcode + the number in the participant code. For example p1 has a password passcode1.
  2. Participants 1 - 6 are for colour vision deficient (CVD) individuals or simulated CVD.
  3. Participants 7 - 12 are for normal colour vision individuals.
  4. Click the thumbnail to view project and follow the page instructions.

Forecaster

Tech: HTML, CSS and JavaScript

This project allows a user to view historical and projected fuel prices.

  • Purpose: A tool designed to display historical fuel prices and a 12-month forecast through “Historical” and “Forecast” modes.
  • Problem: Users need to review past price behaviour and view possible short-term price trends in one chart that shows graphs.
  • Constraints: A two-mode workflow, historical navigation using month controls, and forecast mode that should show 12 months of future projections.

  • Outcome: The user sees a graph with data points for fuel prices related to solid, liquid, gas and electricity.
  1. Pick a mode - historical or forecaster
  2. Historical - use buttons below to view data
  3. Forecaster - a projection of 12 months of future fuel prices are shown

Tech: HTML, CSS and JavaScript (In progress)

This project is a front-end blog website focused on Black hair care and beauty topics. Users can create, read, update, and delete blog posts, demonstrating client-side data management and integrated API usage without a custom backend.

  • Purpose: A front-end blog concept for Black hair care and beauty. It aims to showcase front-end patterns like API consumption, CRUD, and dynamic rendering. This project is currently marked “in progress.”
  • Problem: The goal is to create an editorial-style site with topic navigation and posts. It should also demonstrate modern front-end data patterns.
  • Constraints: The site is still under development. The portfolio shows that the Home, About, and LCO pages are partially developed. The live homepage features repeated “Latest/Trending” blocks and multiple “read more” links.
  • Approach: I built a blog layout with a top navigation menu, topic grouping (Latest Articles, Trending, Blog Topics), article cards that include images and dates, and a subscribe form. This lays the foundation for future API-backed CRUD functionality.
  • Outcome: The early prototype is usable and demonstrates layout, routing intent, and content presentation. However, it feels unfinished due to duplication and incomplete sections.

Currently, the Home, About, and LCO Method pages are partially developed to demonstrate layout structure, routing, and content population driven by API. This project is still under development, with plans to enhance styling, content completeness, and the overall user experience.
